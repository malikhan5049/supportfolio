# TinyURL Implementation Plan (Plan 4)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the shell's disposable identity-card fixture with a real TinyURL project — a Spring Boot service with its own PostgreSQL datastore, a production Angular microfrontend that exposes `card@1.0.0` and runs the full shortener UI at its own origin, a validated manifest, and a deploy-ready pipeline whose load-bearing artifacts (arm64 image, k3s manifests, prod login flow, anonymous surface) are CI-proven at merge time without touching a real cluster.

**Architecture:** `/projects/tinyurl` contains a Spring Boot resource server (`service/`, port 8082) that validates Identity-issued JWTs, stores links and one row per click in a database-per-service PostgreSQL schema migrated by Flyway at boot, serves the built SPA and `remoteEntry.js` from one image, and proxies the four Identity browser endpoints same-origin. The Angular app (`microfrontend/`, port 4201) is one webpack Module Federation container that both exposes `./card` to the shell's runtime registry and boots the full browse/shorten UI with its own login page. The shell is changed only by registry data and configuration: the `identity` entry and fixture disappear, TinyURL's origin becomes trusted, and the shell E2E proves the real remote loaded. Deploy artifacts (Dockerfile, GHCR push, reusable deploy workflow, k3s manifests, environment references) are committed and reviewed, while CI executes the image on ARM, the manifests on a disposable k3s, and the prod login flow against a stub Identity.

**Tech Stack:** Spring Boot 4.1.1 (Java 17), Spring Data JPA, Flyway, PostgreSQL, springdoc OpenAPI, Spring Cloud Gateway Server MVC, Testcontainers PostgreSQL, JUnit 5 + MockMvc; Angular ~22.2.3, Nx 23.3.x, `@angular-architects/module-federation@^22.0.0` (webpack 5.111.0), Jest + `@testing-library/angular`, Playwright ^1.64.1; Docker buildx, GHCR, k3s on a disposable GitHub-hosted runner.

**Spec:** [docs/superpowers/specs/2026-10-20-tinyurl-design.md](../specs/2026-10-20-tinyurl-design.md) — "Goals", "Decided", "Integration Contracts", "Acceptance Criteria". It argues from [the platform design](2026-10-16-portfolio-platform-design.md) and consumes Plan 3 ([shell/gateway](2026-10-20-shell-gateway.md)) as built.

## Scope decisions (my calls, flagged)

The spec delegates these; the plan argues from them.

- **Persistence is Spring Data JPA + explicit Flyway migrations.** UUID primary keys (`uuid`), `created_by` stores the JWT `sub`, `links.target_url` is `text`, `link_clicks` has a cascading FK to `links`. `spring.jpa.hibernate.ddl-auto=validate`; Flyway is the only schema authority and runs at boot.
- **Slugs are 8 characters from the 62-character `[0-9A-Za-z]` alphabet**, generated with `SecureRandom`; creation retries on a unique-key race up to five times. No sequential ids, no custom slugs.
- **The shorten endpoint is rate-limited in-process** with a fixed hourly window keyed by JWT `sub`, default 20/hour, configurable via `supportfolio.tinyurl.rate-limit-per-hour`. The class Javadoc states the horizontal-scaling limitation: each instance has its own window; move the limiter to a shared store only when a second replica exists.
- **`GET /go/{slug}` returns 302** and inserts one `link_clicks` row before redirecting. Unknown slugs return `404 {"error":"link_not_found"}`; invalid targets return `400 {"error":"invalid_target_url"}`; over-cap returns `429 {"error":"rate_limited"}`. The exact typed bodies are a plan decision; the statuses are the spec's.
- **The service is a Spring Cloud Gateway Server MVC consumer**, reusing the shell's `2025.1.3` BOM and proxying exactly `/api/token`, `/auth/login`, `/oauth2/**`, `/login/**` to `supportfolio.tinyurl.identity-uri`. `/auth/callback`, `/signin`, and `/` stay local SPA routes.
- **The image serves the SPA from `file:/app/static/`** (the Dockerfile copies the Nx production output there and the boot jar into `/app/app.jar`; it does no compilation). The dev/test default static location is `classpath:/static/`.
- **The browser-facing short-link base is an Angular environment value**: dev `http://localhost:8082`, prod `''` (relative `/go/...`). It is not baked into the service.
- **The real-card content marker is `data-testid="tinyurl-card-content"`** on the shared `<lib-card>` host. The card never emits `remote-card-tinyurl`; the shell wrapper owns that id.
- **The full app is a single route tree**: `/` (browse + shorten), `/signin`, `/auth/callback`. Browsing and the link list are public; the shorten form gates on `AuthTokenStore.token()`.
- **CI pushes the SHA-tagged arm64 image on pull requests as well as main**, so the ARM smoke and prod-login jobs are real required checks at merge time and the merged SHA's image already exists. GHCR is free on this public repo. This is a deliberate CI-cost/supply-chain trade-off, flagged for review (R3 below).
- **The k3s-in-CI job builds a disposable amd64 image locally** (same Dockerfile) because the shipped arm64 image cannot execute on an amd64 runner; the *manifests* are architecture-independent and are what that job proves. The ARM job separately proves the pushed arm64 artifact executes.
- **Deploy workflow location needs a ruling (R1).** GitHub only registers reusable workflows at the top level of `.github/workflows/`; this repo currently keeps `backend-ci.yml`/`frontend-ci.yml` under `platform/harness/workflows/`, and the platform spec says reusable workflows live there. The plan keeps the canonical files under `platform/harness/workflows/` (so the spec's layout and the hard boundary for `deploy.yml` hold) and adds a generated, byte-identical mirror under `.github/workflows/`, produced by `tools/sync-harness-workflows.ts` and enforced by a test. `tinyurl-ci.yml` calls the top-level mirror. **Do not start Tasks 22–26 until R1 is accepted**; if rejected, choose an alternative (move the canonical files and update the platform spec, or inline the jobs) rather than improvising during execution.
- **The shared auth library's dev default needs a ruling (R4).** The spec requires the production bundle to contain no `localhost:8081`, but `provideAuth()` currently bakes that literal into every consumer. I verified it on the live repo: `npx nx build shell-host` emits the string in `dist/platform/shell/host`. Task 13 therefore makes `identityLoginBaseUrl` an explicit, required argument of `provideAuth` and updates the shell's dev call to pass `http://localhost:8081`; the shell's **prod** gap is unchanged and still deferred. TinyURL passes `environment.identityLoginBaseUrl` (`''` in prod) and the bundle gate then means what the spec says. **Do not start Task 20 until R4 is accepted.** If rejected, stop and report; do not weaken the gate or ship the dev default.
- **`backend-ci.yml` gains a `gradle-module` input** (`projects:tinyurl:service`) and runs `./gradlew :<module>:build`. The existing `-p projects/tinyurl/service build` does not address a subproject of this composite build; the workflow is shared harness code, so the fix applies to every future project (R2).
- **`check-formatting` is widened to `projects/**/*.{ts,html}`** in the same CI task, so the new frontend is actually gated by Prettier (the current glob covers only `platform/` and `tools/`).
- **YAGNI deferrals are not tasks:** custom slugs, link expiry, editing targets, QR codes, charts/per-link analytics, any TinyURL admin UI, browse pagination/search/sorting, scaffold-template extraction, and the shell's own prod-auth gap are all explicitly out of scope. The shell prod-auth gap is recorded for the successor cluster/shell-packaging plan, as the spec requires.
- **Successor work is not executed here:** cluster/VM creation, DNS/TLS, the prod registry entry and prod trusted origin, CD execution, Grafana telemetry, environment-protection activation, and blocking promote-gates. Their artifacts are committed and reviewed; the cluster plan flips them on.

## Global Constraints

- **Versions are pinned to the workspace; do not bump Angular, Spring Boot, or Nx inside this plan:** Java `17`, Spring Boot `4.1.1` (`gradle/libs.versions.toml`), Angular `~22.2.3`, Nx `23.3.x`, `@angular-architects/module-federation` `^22.0.0`, webpack `5.111.0`, Playwright `^1.64.1`.
- **Any new dependency or image tag follows verify-before-pin:** read the official release page at task time, choose the current stable version compatible with the pinned stack, and record the verified version in the commit message body. This covers springdoc, Flyway, the PostgreSQL driver, Testcontainers, the PostgreSQL image tag, the arm64 JRE base image, the k3s version, and every GitHub Action used. If no compatible version exists, stop and escalate — never silently change the pinned framework versions.
- **Database-per-service:** TinyURL owns `links` and `link_clicks` in its own `tinyurl` database. No other project shares the schema; Flyway migrations are the only DDL path; `ddl-auto=validate`.
- **Auth contract is Plan 2's, unchanged:** Identity-issued RS256 JWT; claims `iss/sub/preferred_username/email/name/role/iat/exp`; role is lowercase `admin` or `user`. The service validates the JWT and checks the role itself; no GitHub/Keycloak knowledge lives in TinyURL.
- **The shared `provideAuth` requires an explicit `identityLoginBaseUrl`** (Task 13). Dev callers pass `http://localhost:8081`; prod TinyURL passes `''` through the environment file replacement. No dev Identity URL may remain in the TinyURL production bundle.
- **Public surface is explicit and minimal:** browse list exposes only `slug`, `targetUrl`, `clickCount`, `createdAt`; creator identity never appears in a public payload. Everything not on the documented anonymous list requires authentication.
- **The public API is `/api/links` (GET/POST), `/go/{slug}` (GET), plus the SPA, `remoteEntry.js`, static assets, health probes, and API docs.** REST nouns stay plural and verbs stay out of paths.
- **Clicks are rows:** every successful `/go/{slug}` inserts exactly one `link_clicks` row before the redirect; 302, never 301.
- **Shortening requires `admin` or `user`.** Anonymous → 401; authenticated with any other role → 403; over 20/hour/user → 429; nothing is stored on a rejected request.
- **OpenAPI is published from the running service** (CODING_STANDARDS.md), and the docs are public by the spec's public-repo rationale.
- **Remotes never receive auth tokens.** TinyURL's card is rendered by the shell's wrapper; the shell passes only card metadata. The app's own `authInterceptor` attaches the bearer only to same-origin `/api/` calls minus `/api/token`.
- **No secret is committed.** Dev DB credentials are localhost-only defaults in `docker-compose.yml`; every other environment uses env-only values. The k3s secret is a `.yaml.template` with `${...}` placeholders; CI substitutes dummy values.
- **No PII in logs or telemetry.** Do not log target URLs with user identity, tokens, codes, or emails. Validation warnings name the slug or project id only.
- **This is an auth/input-touching PR:** carry the OWASP checklist item (GOVERNANCE.md Policies) priced as URL validation on shorten, open-redirect/slug-enumeration handling on `/go/{slug}`, rate limiting, and public-field exposure. The tests in Tasks 4, 5, 7, 8, and 12 are the price, not optional extras.
- **Free-tier only:** the only new recurring surface is the GHCR package, free on this public repo; no paid runner, database, or observability service is introduced.
- **Backend style:** package-by-feature, one public class per file, constructor injection only, Google Java Format via Spotless (`spotlessCheck` runs in `build`) — see [CODING_STANDARDS.md](../../../platform/harness/CODING_STANDARDS.md).
- **Frontend style:** standalone components only, one component per file, Prettier is the formatter.
- **Every commit follows Conventional Commits** (`feat:`, `test:`, `ci:`, `docs:`, `chore:`), one logical change per commit. Every change arrives via a PR linking its Issue; merge-to-main and promote-to-prod are never bypassed.
- **TDD is mandatory:** each task writes its test first, runs it to see it fail for the expected reason, implements the minimum, reruns to green, then commits.
- **Do not claim completion without evidence.** Each task's final verification step prints the command and the expected output; UI tasks include the production build. If an integration problem survives one failed hypothesis, invoke `systematic-debugging`; do not patch by guesswork or escalate models for environment failures.
- **Deploy-ready means reviewed, not executed.** Nothing in this plan applies to a real cluster, flips CD on, or provisions cloud resources. The only k3s that runs is the disposable one inside CI.
- **Retrospective compliance:** no mid-plan retrospective entries; one entry at completion, written from the dispatch ledger.

## Review Focus

The spec implies these failure modes; no happy-path test catches them. Each line names the input or condition, the behavior a reasonable person expects, and the owning task(s) whose tests must pin it.

1. **A syntactically valid target URL that resolves to loopback, a private range, link-local metadata (`169.254.169.254`), a unique-local IPv6 address, or carries embedded `user:pass@` credentials** must be rejected with `400 {"error":"invalid_target_url"}` before any row is written — pinned to Task 4 (validator) and Task 5 (endpoint + no-row assertion).
2. **A valid JWT whose role is outside `admin|user`, an anonymous shorten, or a missing/expired token** must produce 401/403 and must never create a link — pinned to Task 5 and the Task 12 matrix.
3. **The 21st shorten in the same hour, the first shorten of the next hour, and a different user's first shorten** must behave correctly: 429 at the boundary, allowed after rollover, independent per user, no row on the 429 — pinned to Task 8.
4. **`/go/{slug}` with an unknown slug vs a known slug** must be 404 vs 302, must use 302 (not 301), and must insert exactly one click row per follow so the browse count increments — pinned to Task 7, and the public/protected status split to Task 12.
5. **The database becomes briefly unreachable after boot** must leave liveness `UP` while readiness reports `DOWN`; Flyway must fail startup loudly on a bad migration rather than letting Hibernate silently create a schema — pinned to Task 3 and Task 11.
6. **After the fixture swap, a registry entry or trusted-origin mismatch silently drops TinyURL and the shell renders the fallback card** — the swap E2E must assert the wrapper's `remote-card-tinyurl`, the real-card marker `tinyurl-card-content`, and the project card, not just "a card appeared" — pinned to Task 19.
7. **The production bundle accidentally retains `localhost:8081`, or prod login resolves off-origin** must fail the build; the same-origin `/auth/login` → stub Identity → `/api/token` → shorten → follow flow must work through the image's own proxy — pinned to Task 13 (explicit auth base), Task 16 (prod environment), Task 20 (bundle gate), and Task 26 (prod login E2E).
