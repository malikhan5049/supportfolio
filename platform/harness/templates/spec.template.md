## Intent

Describe the problem this artifact solves and why it matters. Keep it focused on the single purpose of the spec.

## Goals

List the concrete outcomes this work must achieve. Each goal should be specific, measurable, and tied to user or system value.

## Non-Goals

State what is deliberately out of scope for this spec. This protects the team from scope creep and clarifies boundaries.

## Anti-Goals

Describe outcomes or approaches that must be actively avoided. This is the negative space that prevents solving the wrong problem well.

## Acceptance Criteria

Define the conditions that must be true for this spec to be considered complete. Use clear, verifiable statements.

## Constraints

Document fixed limits the implementation must respect, such as technology choices, compliance requirements, dependencies, or performance targets.
